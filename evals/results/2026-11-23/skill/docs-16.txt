# دليل إعداد بيئة التطوير لمشروع Node.js على ويندوز

يأخذك هذا الدليل من جهاز ويندوز 10 أو 11 خالٍ من أدوات التطوير إلى تشغيل اختبارات المشروع بنجاح. تُنفَّذ الأوامر كلها في الطرفية PowerShell، وأسماء المستودع والملفات الواردة فيه أمثلة تستبدل بها ما يخص مشروعك.

## الخطوة الأولى: تثبيت Git

ثبّت Git بمدير الحزم `winget` المرفق مع ويندوز:

```powershell
winget install Git.Git
```

أغلق الطرفية وافتحها من جديد بعد كل تثبيت حتى يُحدَّث متغير المسارات (`PATH`)، ثم اضبط اسمك وبريدك:

```powershell
git config --global user.name "اسمك"
git config --global user.email "you@example.com"
git config --global core.longpaths true
```

يمنع الإعداد الأخير أخطاء المسارات الطويلة التي تظهر كثيرًا داخل مجلد `node_modules`.

## الخطوة الثانية: تثبيت Node.js

أمامك طريقتان، فاختر واحدة منهما ولا تجمع بينهما.

**الطريقة الأولى: مدير الإصدارات (موصى بها).** يتيح لك `nvm-windows` التبديل بين إصدارات Node حين تختلف متطلبات مشاريعك:

```powershell
winget install CoreyButler.NVMforWindows
```

افتح طرفية جديدة، ثم ثبّت الإصدار طويل الدعم (LTS) وفعّله:

```powershell
nvm install lts
nvm use lts
```

إذا حدّد المشروع إصدارًا بعينه في ملف `.nvmrc` أو في حقل `engines` من ملف `package.json` فثبّت ذلك الإصدار، مثل `nvm install 22.11.0` ثم `nvm use 22.11.0`.

**الطريقة الثانية: التثبيت المباشر.** تكفيك إن كنت تعمل على مشروع واحد:

```powershell
winget install OpenJS.NodeJS.LTS
```

تحقق بعد ذلك من نجاح التثبيت في طرفية جديدة:

```powershell
node --version
npm --version
```

يجب أن يطبع كل أمر رقم إصدار. إذا ظهرت عند تنفيذ `npm` رسالة تفيد بأن تشغيل السكربتات معطّل، فاسمح به لحسابك ثم أعد المحاولة:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## الخطوة الثالثة: جلب المشروع

انسخ المستودع إلى مسار قصير لا يحوي مسافات ولا حروفًا غير لاتينية، مثل `C:\dev`، وابتعد عن المجلدات التي يزامنها OneDrive لأن المزامنة تبطئ العمل في `node_modules` وتقفل ملفاته:

```powershell
mkdir C:\dev
cd C:\dev
git clone https://github.com/example/my-project.git
cd my-project
```

## الخطوة الرابعة: تثبيت الاعتماديات

```powershell
npm ci
```

يثبّت `npm ci` الإصدارات المسجلة في ملف `package-lock.json` بلا تغيير، فتطابق بيئتك بيئة بقية الفريق. إذا خلا المشروع من هذا الملف فاستخدم `npm install`.

بعض المشاريع تعتمد مدير حزم آخر، ويدلّك عليه ملف القفل الموجود في جذر المشروع:

| ملف القفل | الأمر |
| --- | --- |
| `package-lock.json` | `npm ci` |
| `pnpm-lock.yaml` | `corepack enable` ثم `pnpm install --frozen-lockfile` |
| `yarn.lock` | `corepack enable` ثم `yarn install --immutable` (أو `--frozen-lockfile` في الإصدار الأول من Yarn) |

## الخطوة الخامسة: ضبط متغيرات البيئة

إذا وجدت في المشروع ملفًا نموذجيًّا مثل `.env.example` فانسخه ثم عدّل قيمه بما يناسب جهازك:

```powershell
Copy-Item .env.example .env
```

لا تُضِف ملف `.env` إلى Git، فهو يحوي في العادة مفاتيح وكلمات مرور.

## الخطوة السادسة: تشغيل الاختبارات

```powershell
npm test
```

ينفّذ هذا الأمر سكربت `test` المعرّف في قسم `scripts` من ملف `package.json`. اعرض السكربتات المتاحة كلها بالأمر `npm run`، فقد تجد فيها ما يفيدك مثل `lint` و`build`.

يدل رمز الخروج 0 وملخص خالٍ من الإخفاقات على أن البيئة جاهزة. وإذا أردت تشغيل ملف اختبار واحد فمرّر مساره بعد شرطتين:

```powershell
npm test -- tests/user.test.js
```

## مشكلات شائعة على ويندوز

| العَرَض | السبب | الحل |
| --- | --- | --- |
| الأمر `node` أو `npm` غير معروف | الطرفية فُتحت قبل التثبيت | افتح طرفية جديدة |
| خطأ من `node-gyp` أثناء التثبيت | حزمة تحتاج إلى بناء شيفرة أصلية | ثبّت أدوات البناء بالأمر `winget install Microsoft.VisualStudio.2022.BuildTools` واختر منها حمل العمل الخاص بتطوير سطح المكتب بلغة ++C، وثبّت Python كذلك |
| خطأ `EPERM` أو `EBUSY` عند التثبيت | برنامج آخر يقفل الملفات | أغلق المحرر وخادم التطوير، واحذف `node_modules` ثم أعد `npm ci` |
| سكربت يفشل عند صيغة مثل `NODE_ENV=test` | صيغة خاصة بصدفة Bash | استخدم حزمة `cross-env` في السكربت، أو شغّله من Git Bash |
| أداة التنسيق تشكو من نهايات الأسطر في كل ملف | حوّل Git النهايات إلى `CRLF` | نفّذ `git config --global core.autocrlf input` ثم أعد نسخ المستودع |

إذا كان المشروع يعتمد كثيرًا على أدوات لينكس وسكربتات Bash، فالأيسر أن تعمل داخل نظام ويندوز الفرعي للينكس (WSL): ثبّته بالأمر `wsl --install` ثم اتبع خطوات لينكس داخله.
