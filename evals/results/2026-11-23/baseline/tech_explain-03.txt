## كيف يعمل `git rebase`

يأخذ `rebase` الـ commits الخاصة بفرعك، ثم يعيد تطبيقها واحدًا تلو الآخر فوق نقطة بداية جديدة، وهي عادةً آخر commit في `main`.

**قبل:**
```
main:     A---B---C---D
               \
feature:        E---F
```

**بعد `git rebase main` وأنت على `feature`:**
```
main:     A---B---C---D
                       \
feature:                E'---F'
```

`E'` و`F'` commits جديدة بمحتوى `E` و`F` نفسه، لكن لكل منها hash مختلف لأن الأب تغيّر. أي أن rebase **يعيد كتابة التاريخ**.

**أما `merge`** فيُبقي التاريخ كما هو ويضيف commit دمج جديدًا:
```
main:     A---B---C---D---M
               \         /
feature:        E-------F
```

---

## متى تفضّل rebase على merge؟

**استخدم `rebase` عندما:**
- تريد تحديث فرعك المحلي بآخر تغييرات `main` قبل فتح Pull Request.
- تريد تاريخًا خطيًا نظيفًا بلا merge commits كثيرة لا تضيف معلومة.
- تريد ترتيب commits فرعك قبل مشاركته، مثل دمج commits صغيرة أو تعديل رسائلها عبر `rebase -i`.

**استخدم `merge` عندما:**
- يكون الفرع **منشورًا ويعمل عليه آخرون**، لأن rebase يغيّر الـ hashes فيُربك من سحبوا الفرع.
- تريد الحفاظ على سجل دقيق لوقت دمج كل ميزة.
- تدمج فرعًا مكتملًا في `main`.

**القاعدة الذهبية:** لا تعمل rebase لـ commits دفعتها إلى فرع مشترك يعتمد عليه غيرك.

---

## مثال عملي

```bash
# أنت على فرع الميزة
git switch feature

# اجلب آخر التحديثات من المستودع البعيد
git fetch origin

# أعد تطبيق commits فرعك فوق آخر main
git rebase origin/main
```

**إذا ظهر تعارض (conflict):**
```bash
# حلّ التعارض في الملفات، ثم:
git add <file>
git rebase --continue

# أو ألغِ العملية كلها وارجع لما كنت عليه:
git rebase --abort
```

**ادفع الفرع بعد rebase:** لأن التاريخ تغيّر ستحتاج إلى force، واستخدم النسخة الآمنة:
```bash
git push --force-with-lease
```

**ترتيب آخر 3 commits قبل الـ PR:**
```bash
git rebase -i HEAD~3
# في المحرر غيّر pick إلى squash (أو s) لدمج commit مع الذي قبله
```

---

## الخلاصة

| | `rebase` | `merge` |
|---|---|---|
| التاريخ | خطي ونظيف | يحفظ التفرعات كما حدثت |
| يغيّر الـ hashes | نعم | لا |
| آمن على فرع مشترك | لا | نعم |
| الاستخدام الأمثل | تحديث فرعك الخاص وتنظيفه | دمج فرع مكتمل أو مشترك |

**سير عمل شائع:** استخدم `rebase` على فرعك الخاص ليبقى محدّثًا ونظيفًا، ثم `merge` (أو squash merge عبر الـ PR) لدمجه في `main`.
