الـ **recursion** (الاستدعاء الذاتي) هو أن تستدعي الدالة نفسها لحل نسخة أصغر من المسألة نفسها، وتكرر ذلك حتى تصل إلى حالة بسيطة تُحل مباشرة.

كل دالة recursive تحتاج جزأين:

1. **الحالة الأساسية (base case):** الشرط الذي يوقف الاستدعاء. بدونه تستمر الدالة في استدعاء نفسها حتى يمتلئ الـ call stack ويظهر الخطأ `RangeError: Maximum call stack size exceeded`.
2. **الحالة التكرارية (recursive case):** استدعاء الدالة لنفسها بمُدخل أصغر يقترب من الحالة الأساسية.

## مثال: المضروب (factorial)

المضروب يناسب هذا الأسلوب لأن تعريفه الرياضي نفسه recursive:

- `n! = n × (n-1)!`
- `0! = 1`

```javascript
function factorial(n) {
  if (n < 0) {
    throw new RangeError("المضروب غير معرّف للأعداد السالبة");
  }

  // الحالة الأساسية
  if (n === 0 || n === 1) {
    return 1;
  }

  // الحالة التكرارية
  return n * factorial(n - 1);
}

console.log(factorial(5)); // 120
```

## ماذا يحدث عند استدعاء `factorial(4)`؟

تتراكم الاستدعاءات في الـ call stack حتى الوصول إلى الحالة الأساسية، ثم تُحسب النتائج في طريق العودة:

```
factorial(4)
= 4 * factorial(3)
= 4 * (3 * factorial(2))
= 4 * (3 * (2 * factorial(1)))
= 4 * (3 * (2 * 1))
= 4 * (3 * 2)
= 4 * 6
= 24
```

## ملاحظات عملية

- **عمق الاستدعاء محدود:** كل استدعاء يحجز إطارًا في الـ stack، لذا القيم الكبيرة جدًا لـ `n` (عشرات الآلاف) تسبب stack overflow. في هذه الحالة تكون الحلقة العادية (`for`) أنسب.
- **دقة الأرقام:** نوع `Number` في JavaScript يفقد الدقة بعد `170!` تقريبًا (يصبح `Infinity`)، وقبل ذلك تبدأ الأخطاء من `18!` فصاعدًا لتجاوز `Number.MAX_SAFE_INTEGER`. للقيم الكبيرة استخدم `BigInt`.
- **متى يُستخدم الـ recursion؟** يناسب المسائل ذات البنية المتداخلة بطبيعتها، مثل التنقل في الأشجار (DOM، مجلدات الملفات، JSON متداخل) وخوارزميات divide and conquer مثل merge sort.
