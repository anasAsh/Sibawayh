## ما هو الـ Docker Container؟

الحاوية (Container) هي وحدة معزولة تضم تطبيقك وكل ما يحتاجه للتشغيل: الكود والمكتبات والاعتماديات وملفات الإعداد وأدوات النظام اللازمة. تُبنى الحاوية من **صورة (Image)**، وهي قالب ثابت للقراءة فقط يُعرَّف عادةً في ملف `Dockerfile`. تشغيل الصورة يعطيك حاوية حيّة.

مثال بسيط على `Dockerfile`:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]
```

ثم:
```bash
docker build -t myapp .
docker run -p 8000:8000 myapp
```

## الفرق بينها وبين الآلة الافتراضية (VM)

الفرق الأساسي في **ما الذي يتم عزله ومحاكاته**:

```
     الآلة الافتراضية                  الحاوية
┌─────────┬─────────┐          ┌─────────┬─────────┐
│ تطبيق A │ تطبيق B │          │ تطبيق A │ تطبيق B │
├─────────┼─────────┤          ├─────────┼─────────┤
│ مكتبات  │ مكتبات  │          │ مكتبات  │ مكتبات  │
├─────────┼─────────┤          └─────────┴─────────┘
│ نظام    │ نظام    │          ┌───────────────────┐
│ ضيف كامل│ ضيف كامل│          │   Docker Engine   │
└─────────┴─────────┘          ├───────────────────┤
┌───────────────────┐          │ نواة نظام المضيف  │
│    Hypervisor     │          │   (Kernel مشترك)  │
├───────────────────┤          ├───────────────────┤
│     العتاد        │          │      العتاد       │
└───────────────────┘          └───────────────────┘
```

| المعيار | الآلة الافتراضية | الحاوية |
|---|---|---|
| **مستوى المحاكاة** | تحاكي عتادًا كاملًا عبر Hypervisor | تعزل العمليات على مستوى نظام التشغيل |
| **نظام التشغيل** | لكل VM نظام ونواة (Kernel) خاصة بها | كل الحاويات تتشارك نواة المضيف |
| **الحجم** | عدة غيغابايتات | من بضعة ميغابايتات إلى مئات منها |
| **زمن الإقلاع** | دقائق | ثوانٍ أو أجزاء من الثانية |
| **استهلاك الموارد** | مرتفع، فلكل VM ذاكرة ونظام كامل | منخفض، فيمكن تشغيل عشرات الحاويات على جهاز واحد |
| **قوة العزل** | أقوى، لأن النواة منفصلة | أضعف نسبيًا، لأن النواة مشتركة |
| **تنوع الأنظمة** | يمكن تشغيل Windows على مضيف Linux | الحاوية يجب أن تناسب نواة المضيف (Linux على Linux) |

**من الناحية التقنية:** تعتمد الحاويات على ميزات في نواة Linux:
- **Namespaces** لعزل ما تراه العملية: العمليات والشبكة ونظام الملفات والمستخدمين.
- **cgroups** لتحديد ما تستهلكه العملية من معالج وذاكرة وإدخال/إخراج.
- **Union filesystems** (مثل OverlayFS) لبناء الصورة على شكل طبقات يُعاد استخدامها.

يعني هذا أن الحاوية في الحقيقة عملية عادية على نظام المضيف، لكنها تعمل داخل "فقاعة" معزولة.

## لماذا يفضّلها المطورون؟

1. **حل مشكلة "يعمل على جهازي فقط"**: البيئة نفسها تعمل على جهاز المطور وخادم الاختبار وبيئة الإنتاج، لأن كل الاعتماديات موجودة داخل الصورة.

2. **السرعة**: الإقلاع شبه فوري، فتصبح دورة "عدّل ثم ابنِ ثم اختبر" أسرع، ويصبح التوسع السريع (Scaling) ممكنًا.

3. **الخفة والكفاءة**: تستطيع تشغيل قاعدة بيانات وخادم Redis وتطبيقك وخدمة رسائل معًا على حاسوب محمول دون أن يثقل.

4. **عزل الاعتماديات**: مشروع يحتاج Python 3.8 وآخر يحتاج 3.12؟ تضع كل واحد في حاويته دون تعارض.

5. **البنية كرمز (Infrastructure as Code)**: ملف `Dockerfile` و`docker-compose.yml` يوثّقان البيئة بدقة، ويُحفظان في Git، ويُراجَعان مثل أي كود.

6. **ملاءمة الخدمات المصغّرة (Microservices)**: كل خدمة في حاويتها، وتُنشر وتُحدَّث وتُوسَّع وحدها. وهذا أساس أدوات التنسيق مثل **Kubernetes**.

7. **تكامل سلس مع CI/CD**: تُبنى الصورة مرة واحدة، ثم تُختبر وتُنشر كما هي، فلا تحدث مفاجآت بين المراحل.

8. **نظام بيئي غني**: على Docker Hub آلاف الصور الجاهزة، فتشغيل PostgreSQL مثلًا يأخذ أمرًا واحدًا:
   ```bash
   docker run -e POSTGRES_PASSWORD=secret -p 5432:5432 postgres
   ```

## متى تبقى الآلة الافتراضية الخيار الأفضل؟

- عندما تحتاج **عزلًا أمنيًا قويًا**، مثل تشغيل كود غير موثوق أو بيئة متعددة العملاء بمتطلبات صارمة.
- عندما تحتاج **نظام تشغيل مختلفًا** عن المضيف، أو نواة معدّلة.
- مع التطبيقات القديمة التي تتوقع نظامًا كاملًا بكل خدماته.

في الواقع يُستخدم الاثنان معًا كثيرًا، فمعظم الحاويات في السحابة تعمل داخل آلات افتراضية، لتحصل على مرونة الحاويات وعزل الـ VM في الوقت نفسه.

**الخلاصة:** الآلة الافتراضية تشبه بناء منزل مستقل لكل تطبيق، والحاوية تشبه شققًا منفصلة في عمارة واحدة تتشارك الأساسات (النواة)، ولكل شقة بابها ومحتوياتها. لذلك الحاويات أخف وأسرع وأسهل في النقل، وهذا سبب انتشارها الكبير بين المطورين.
