انتهيت من مراجعة الشرح لغويًّا، وهذه صيغته النهائية.

ينقل `git rebase` إيداعات فرعك (commits) لتبدأ من أحدث نقطة في فرع آخر، فيصبح التاريخ خطًّا مستقيمًا. أما `git merge` فيجمع الفرعين ويُبقي تاريخهما كما حدث. والقاعدة المختصرة: **أعِد التأسيس (rebase) في فرعك الخاص، واستخدم الدمج (merge) في الفروع المشتركة.**

## كيف يعمل

لنفترض أنك أنشأت الفرع `feature` من الإيداع `B`، ثم تقدّم `main` إلى `D`:

```text
A---B---C---D      main
     \
      E---F        feature
```

عند تنفيذ `git rebase main` وأنت في `feature`:

1. يبحث الأمر عن الإيداعات الموجودة في فرعك وغير الموجودة في `main`، وهي هنا `E` و`F`.
2. ينتقل إلى رأس `main`، أي `D`.
3. يعيد تطبيق تغييرات كل إيداع بالترتيب، ثم يوجّه `feature` إلى آخر إيداع جديد.

```text
A---B---C---D              main
             \
              E'---F'      feature
```

الإيداعان `E'` و`F'` جديدان، ومعرّفاهما (hashes) مختلفان عن الأصل حتى لو تطابقت التغييرات، لأن الإيداع الأب تغيّر. ولهذا نقول إن إعادة التأسيس تعيد كتابة التاريخ.

أما `git merge main` فلا يغيّر `E` ولا `F`، بل يضيف إيداع دمج `M` له أبوان:

```text
A---B---C---D      main
     \       \
      E---F---M    feature
```

## متى تفضّل كلًّا منهما

| الحالة | الأنسب |
|---|---|
| تحديث فرعك الخاص بآخر ما في `main` | `rebase` |
| ترتيب إيداعاتك قبل طلب الدمج (pull request) | `rebase -i` |
| جلب التحديثات من دون إيداعات دمج زائدة | `git pull --rebase` |
| فرع يعمل عليه غيرك | `merge` |
| إدخال ميزة مكتملة في `main` مع إبقاء أثر الدمج | `merge --no-ff` |
| فرع طويل كثير التعارضات | `merge` غالبًا، لأنك تحل التعارض مرة واحدة، وقد يتكرر مع كل إيداع في إعادة التأسيس |

## مثال

حدّث فرعك ثم ارفعه:

```bash
git switch feature
git fetch origin
git rebase origin/main
git push --force-with-lease   # إن سبق أن رفعت الفرع
```

وإذا ظهر تعارض، فعدّل الملفات ثم أكمل:

```bash
git add <file>
git rebase --continue   # أو git rebase --abort للعودة إلى ما قبل البدء
```

وبعد ذلك أدخل الميزة في `main`:

```bash
git switch main
git pull --ff-only
git merge --no-ff feature
```

## تنبيهان

- **لا تُعِد تأسيس إيداعات بنى عليها غيرك:** ستختلف نسختك عن نسخهم، فتتكرر الإيداعات والتعارضات.
- **استخدم `--force-with-lease` بدل `--force`:** يرفض الرفع إذا تغيّر الفرع البعيد عمّا تعرفه نسختك المحلية، فيقلّ احتمال محو عمل غيرك. لكنه لا يحميك إن نفّذت `git fetch` ولم تراجع ما وصل.

وإن أخطأت بعد انتهاء العملية، فاعرض الحالات السابقة بالأمر `git reflog`، ثم ارجع إلى الحالة المطلوبة بالأمر `git reset --hard <hash>`. احفظ تغييراتك غير المودعة أولًا، لأن هذا الأمر يحذفها.
