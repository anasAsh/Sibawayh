جامع المهملات (garbage collector) جزء من بيئة التشغيل يحرّر ذاكرة الكائنات التي لم يعد البرنامج قادرًا على الوصول إليها. تعتمد Java على **تتبّع الكائنات الحية**، وتعتمد Python أساسًا على **عدّ المراجع**، ومن هذا الفرق تأتي أسباب البطء المختلفة في كل منهما.

## كيف يعمل في Java؟

ينطلق الجامع من **الجذور** (GC roots)، مثل المتغيرات المحلية في مكدّس كل خيط والمتغيرات الساكنة، ثم يتبع المراجع من كائن إلى آخر. كل ما يصل إليه حيّ، وما عداه مهملات. لذلك لا تمثّل المراجع الدائرية مشكلة: إذا أشار كائنان أحدهما إلى الآخر ولم يصل إليهما أي جذر، حُرّرا معًا.

ولأن معظم الكائنات يموت بعد إنشائه بقليل، تقسّم أغلب الجوامع الكومة (heap) إلى جيلين:

- **الجيل الصغير:** تُنشأ فيه الكائنات الجديدة عادةً. يكون جمعه متكررًا وسريعًا غالبًا، لأن الجامع ينسخ الأحياء القليلة ويستعيد بقية المساحة دفعة واحدة. أي أن التكلفة تتبع عدد الأحياء وحجمها، لا كمية المهملات.
- **الجيل القديم:** تُرقّى إليه الكائنات التي نجت من عدة دورات. جمعه أندر وأعلى تكلفة.

تختلف الجوامع المتاحة في طريقة الموازنة بين الإنتاجية وزمن التوقف:

| الجامع | الهدف | طبيعة التوقف |
|---|---|---|
| التسلسلي (Serial) | الكومات الصغيرة والموارد المحدودة | يوقف البرنامج ويجمع بخيط واحد |
| المتوازي (Parallel) | أعلى إنتاجية، كالمعالجة الدفعية | يوقف البرنامج ويجمع بعدة خيوط |
| المعتمد على المناطق (G1) | توازن بين الاثنين، وهو الافتراضي على معظم الخوادم | توقفات قصيرة تستهدف 200 ميلي ثانية افتراضيًا، دون ضمان |
| منخفض التوقف (ZGC) | أدنى زمن توقف، حتى مع الكومات الضخمة | أقل من ميلي ثانية عادةً، مقابل استهلاك أكبر للمعالج والذاكرة |

## كيف يعمل في Python؟

الكلام هنا عن التنفيذ المرجعي (CPython)، وفيه آليتان:

**الآلية الأولى: عدّ المراجع.** يحمل كل كائن عدّادًا يزيد مع كل مرجع جديد وينقص مع زوال مرجع، فإذا بلغ الصفر حُرّر الكائن فورًا:

```python
a = [1, 2, 3]   # مرجع واحد
b = a           # مرجعان
del a           # مرجع واحد
del b           # صفر: يُحرَّر الكائن فورًا
```

**الآلية الثانية: كاشف الدورات.** لا يكفي العدّ وحده مع المراجع الدائرية، لأن عدّاداتها لا تبلغ الصفر أبدًا:

```python
class Node:
    pass

x, y = Node(), Node()
x.other, y.other = y, x
del x, y        # لا سبيل إليهما، لكن كل عدّاد ما زال 1
```

لذا تفحص وحدة `gc` دوريًا الكائنات التي قد تحتوي مراجع إلى غيرها، كالقوائم والقواميس. تطرح المراجع الداخلية بين هذه الكائنات من عدّاداتها، فما لم يبقَ له مرجع خارجي، ولا يصل إليه كائن له مرجع خارجي، يُعدّ مهملًا. ويقوم هذا الفحص أيضًا على فكرة الأجيال، وتختلف تفاصيله بين الإصدارات.

## متى يسبب بطئًا؟

### في Java

- **معدل إنشاء مرتفع:** إنشاء كائنات مؤقتة كثيرة داخل حلقات كثيفة التنفيذ يكرّر جمع الجيل الصغير.
- **كومة شبه ممتلئة:** كلما ضاقت المساحة الحرة تكرّر الجمع، وقد يقضي البرنامج معظم وقته فيه قبل أن يظهر `OutOfMemoryError`.
- **جمع كامل (Full GC):** يوقف البرنامج كله ليجمع الكومة، وقد يستغرق ثواني في الكومات الكبيرة. يحدث مثلًا حين يعجز الجامع المعتمد على المناطق عن تحرير الذاكرة بالسرعة الكافية.
- **تسرّب الذاكرة:** إن احتفظت مجموعة ساكنة أو ذاكرة تخزين مؤقت بلا حدّ بكائنات لا يحتاج إليها البرنامج، بقيت حية في نظر الجامع وزاد عمله.
- **ترقية مبكرة:** إذا كان الجيل الصغير ضيقًا، انتقلت إلى الجيل القديم كائنات قصيرة العمر، فكثر جمعه.

### في Python

- **تكلفة دائمة لعدّ المراجع:** هي موزعة على التنفيذ كله، فلا تظهر توقفًا مفاجئًا.
- **إنشاء ملايين الكائنات المعمّرة:** عند بناء بنية بيانات ضخمة، قد يتكرر فحص الكائنات دون أن يجد الكاشف ما يحرّره.
- **تحرير بنية ضخمة:** حذف آخر مرجع إلى قائمة فيها ملايين الكائنات قد يحرّرها كلها دفعة واحدة، فيحدث توقف ملحوظ.
- **توقف الخيوط:** يعمل الكاشف وهو ممسك بالقفل العام للمفسّر (GIL) في النسخة المعتادة، فلا تنفّذ الخيوط الأخرى شيفرة Python في أثنائه.
- **عمليات متفرعة بـ `fork`:** تغيير العدّادات يكتب في صفحات الذاكرة المشتركة فينسخها نظام التشغيل، فيزداد استهلاك الذاكرة.

## ماذا تفعل؟

ابدأ بالقياس، فكثيرًا ما يكون سبب البطء استعلامًا أو خوارزمية لا جامع المهملات:

```bash
java -Xlog:gc* -jar app.jar
```

```python
import gc
gc.set_debug(gc.DEBUG_STATS)
```

ثم عالج السبب بهذا الترتيب:

1. **أصلح التسرّب** واجعل لكل ذاكرة تخزين مؤقت حدًّا أقصى. ابحث في سجل Java عن حجم الكومة بعد كل جمع للجيل القديم: إذا ظل يرتفع تحت حمل ثابت، فالتسرّب مرجّح.
2. **قلّل الإنشاء** في المسارات كثيفة التنفيذ: استخدم `StringBuilder` داخل الحلقات في Java، والمولّدات بدل القوائم الوسيطة في Python.
3. **اضبط الإعدادات أخيرًا:** وسّع الكومة بـ `-Xmx`، أو اختر جامعًا آخر مثل `-XX:+UseZGC`. وفي Python ارفع العتبة بـ `gc.set_threshold`، أو استدعِ `gc.freeze` قبل `fork`.

قد يفيد أيضًا تعطيل الكاشف مؤقتًا بـ `gc.disable` في أثناء تحميل بيانات كثيرة، ثم إعادته بـ `gc.enable`. يبقى عدّ المراجع عاملًا خلال ذلك، لكن المراجع الدائرية تتراكم حتى تعيد تشغيل الكاشف.
