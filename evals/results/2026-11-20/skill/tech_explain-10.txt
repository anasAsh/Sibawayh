## ما الاختبارات الآلية؟

اختبار الوحدة (Unit Test) شيفرة صغيرة تكتبها لتتحقق من أن جزءًا محددًا من برنامجك، كدالة واحدة مثلًا، يعطي النتيجة المتوقعة. تستدعي الدالة بمدخلات معروفة، ثم تقارن ما أعادته بالنتيجة الصحيحة. وإذا اختلفتا، فشل الاختبار ونبّهك إلى الخطأ.

وتُسمّى «آلية» لأنك تشغّلها بأمر واحد في أي وقت، فلا تحتاج إلى تجربة البرنامج يدويًّا في كل مرة.

## لماذا نكتبها؟

- **اكتشاف الأخطاء مبكرًا:** تظهر المشكلة في وقت كتابة الشيفرة، قبل أن تصل إلى المستخدمين.
- **التعديل بثقة:** عندما تعيد هيكلة الشيفرة (Refactoring) أو تضيف ميزة، تخبرك الاختبارات فورًا إن كسرت شيئًا كان يعمل.
- **توثيق حيّ:** يوضح الاختبار كيف تُستخدم الدالة وما السلوك المتوقع منها، ويبقى صحيحًا ما دام ينجح.
- **تصميم أفضل:** الشيفرة التي يسهل اختبارها تكون غالبًا مقسّمة إلى أجزاء صغيرة، لكل منها مهمة واضحة.
- **توفير الوقت:** تشغيل مئات الاختبارات يستغرق بضع ثوانٍ، أما الفحص اليدوي فقد يستغرق ساعات.

## مثال بلغة بايثون

لنفترض أن لدينا دالة تحسب السعر بعد الخصم، في ملف اسمه `pricing.py`:

```python
def apply_discount(price, percent):
    """تعيد السعر بعد تطبيق نسبة الخصم."""
    if price < 0:
        raise ValueError("السعر لا يمكن أن يكون سالبًا")
    if not 0 <= percent <= 100:
        raise ValueError("نسبة الخصم يجب أن تكون بين 0 و100")
    return round(price * (1 - percent / 100), 2)
```

نكتب اختباراتها في ملف منفصل اسمه `test_pricing.py` باستخدام مكتبة `pytest`:

```python
import pytest
from pricing import apply_discount


def test_normal_discount():
    assert apply_discount(100, 20) == 80


def test_no_discount():
    assert apply_discount(50, 0) == 50


def test_full_discount():
    assert apply_discount(50, 100) == 0


def test_rounding():
    assert apply_discount(19.99, 15) == 16.99


def test_negative_price_raises_error():
    with pytest.raises(ValueError):
        apply_discount(-10, 20)


def test_invalid_percent_raises_error():
    with pytest.raises(ValueError):
        apply_discount(100, 150)
```

ثم نثبّت المكتبة ونشغّل الاختبارات:

```bash
pip install pytest
pytest
```

فتظهر نتيجة مثل:

```
test_pricing.py ......                                   [100%]
6 passed in 0.01s
```

## ماذا يحدث عند الخطأ؟

لنفترض أن أحدهم أخطأ لاحقًا فكتب `price * percent / 100` بدلًا من `price * (1 - percent / 100)`. عندها ستعيد الدالة `20` بدلًا من `80` في الاختبار الأول، وسيعرض `pytest` رسالة فشل تذكر اسم الاختبار والقيمتين المختلفتين. بهذا يُكتشف الخطأ فورًا قبل أن يصل إلى بيئة الإنتاج.

## نصائح سريعة

- اختبر الحالة العادية، والحالات الحدّية (مثل 0 و100)، والمدخلات الخاطئة.
- اجعل كل اختبار يتحقق من سلوك واحد، وسمّه اسمًا يصف هذا السلوك.
- اجعل الاختبارات مستقلة بعضها عن بعض، فلا يعتمد أحدها على نتيجة غيره.
