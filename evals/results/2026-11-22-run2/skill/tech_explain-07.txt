## ما معنى نقل الحالة التمثيلية (REST)؟

**واجهة برمجة التطبيقات (API)** وسيطٌ يسمح لبرنامجين بتبادل البيانات وفق قواعد متفق عليها. أما **نقل الحالة التمثيلية (REST)** فأسلوبٌ معماري لتصميم هذه الواجهات على الويب، وضعه روي فيلدينغ (Roy Fielding) عام 2000، ويعتمد على بروتوكول نقل النص التشعبي (HTTP).

تقوم هذه الواجهات على عدة مبادئ، أهمها:

- **الموارد:** كل شيء في النظام مورد، كالمستخدم أو المنتج أو طلب الشراء، ولكل مورد عنوان خاص به، مثل `/users/42`.
- **انعدام الحالة (Stateless):** يحمل كل طلب كل ما يلزم لتنفيذه، ولا يحتفظ الخادم بأي معلومات عن الطلبات السابقة.
- **الفصل بين العميل والخادم:** يمكن تطوير كل طرف وحده ما دامت الواجهة بينهما ثابتة.
- **واجهة موحدة:** تحدد طريقة البروتوكول العملية المطلوبة، ويبيّن رمز الحالة (Status Code) نتيجتها.
- **تمثيل البيانات:** تُرسَل الموارد في الغالب بصيغة ترميز كائنات جافاسكربت (JSON).

## أشهر طرق بروتوكول نقل النص التشعبي

تقابل الطرق الأربع الأشهر عمليات الإنشاء والقراءة والتحديث والحذف (CRUD) في قواعد البيانات. تستخدم الأمثلة التالية خادمًا افتراضيًّا يدير قائمة مستخدمين.

### طريقة `GET`: جلب البيانات

تقرأ هذه الطريقة موردًا أو قائمة موارد ولا تغيّر شيئًا على الخادم، ولذلك توصف بأنها طريقة آمنة.

```http
GET /api/users/42 HTTP/1.1
Host: example.com
```

الاستجابة:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{ "id": 42, "name": "أحمد", "email": "ahmed@example.com" }
```

### طريقة `POST`: إنشاء مورد جديد

ترسل هذه الطريقة بيانات إلى الخادم لينشئ منها موردًا جديدًا. ويحدد الخادم في العادة معرّف المورد الجديد.

```http
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json

{ "name": "سارة", "email": "sara@example.com" }
```

الاستجابة:

```http
HTTP/1.1 201 Created
Location: /api/users/43

{ "id": 43, "name": "سارة", "email": "sara@example.com" }
```

### طريقة `PUT`: تحديث مورد أو استبداله

تستبدل هذه الطريقة المورد كله بالبيانات المرسَلة، فإن أغفلت حقلًا فقد يُحذف من المورد. وإذا كررت الطلب نفسه فستحصل على النتيجة نفسها في كل مرة.

```http
PUT /api/users/43 HTTP/1.1
Host: example.com
Content-Type: application/json

{ "name": "سارة علي", "email": "sara.ali@example.com" }
```

الاستجابة:

```http
HTTP/1.1 200 OK

{ "id": 43, "name": "سارة علي", "email": "sara.ali@example.com" }
```

### طريقة `DELETE`: حذف مورد

تحذف هذه الطريقة المورد الموجود في العنوان المحدد.

```http
DELETE /api/users/43 HTTP/1.1
Host: example.com
```

الاستجابة:

```http
HTTP/1.1 204 No Content
```

## ملخص سريع

| الطريقة | العملية | مثال على العنوان | رمز النجاح المعتاد |
|---|---|---|---|
| `GET` | قراءة | `/api/users/42` | `200 OK` |
| `POST` | إنشاء | `/api/users` | `201 Created` |
| `PUT` | تحديث كامل | `/api/users/43` | `200 OK` |
| `DELETE` | حذف | `/api/users/43` | `204 No Content` |

**ملاحظة:** هناك طريقة خامسة شائعة هي `PATCH`، وتحدّث جزءًا من المورد فقط، أما `PUT` فتستبدل المورد كله.

## تجربة عملية بأداة `curl`

يمكنك تجربة هذه الطرق من سطر الأوامر:

```bash
curl https://example.com/api/users/42
curl -X POST -H "Content-Type: application/json" -d '{"name":"سارة"}' https://example.com/api/users
curl -X PUT -H "Content-Type: application/json" -d '{"name":"سارة علي"}' https://example.com/api/users/43
curl -X DELETE https://example.com/api/users/43
```
