## كيف يعمل `git rebase`؟

تنقل إعادة التأسيس (rebase) إيداعات فرعك إلى قاعدة جديدة. تبحث الأداة أولًا عن الإيداع المشترك بين فرعك والفرع الهدف، ثم تحفظ الإيداعات التي أضفتها بعده، وتنقل فرعك إلى آخر إيداع في الفرع الهدف، ثم تعيد تطبيق إيداعاتك واحدًا تلو الآخر.

النتيجة سجل خطي، كأنك بدأت العمل من أحدث نسخة. لكن الإيداعات الناتجة **جديدة** ولها معرّفات مختلفة، فإعادة التأسيس تعيد كتابة السجل.

```
قبل:                     بعد rebase:
      A---B  feature                   A'--B'  feature
     /                                /
C---D---E  main          C---D---E  main
```

أما الدمج (merge) فلا يغيّر أي إيداع موجود، بل يضيف إيداع دمج يجمع الفرعين، فيبقى السجل متفرعًا كما حدث فعلًا.

## مثال عملي

```bash
git switch feature
git fetch origin
git rebase origin/main        # أعد تطبيق إيداعاتك فوق أحدث main

# عند حدوث تعارض:
git add <file>                # بعد حل التعارض يدويًا
git rebase --continue         # أو: git rebase --abort للتراجع

git push --force-with-lease   # الدفع بالقوة مطلوب لأن السجل تغيّر
```

ولترتيب إيداعاتك قبل فتح طلب الدمج، استخدم الوضع التفاعلي:

```bash
git rebase -i HEAD~3          # ادمج آخر 3 إيداعات أو أعد تسميتها أو احذفها
```

## متى تفضّل إعادة التأسيس؟

- لتحديث فرعك المحلي بآخر تغييرات `main` دون إيداعات دمج متكررة.
- لتنظيف إيداعاتك (دمجها أو إعادة صياغة رسائلها) قبل المراجعة.
- حين يفضّل فريقك سجلًا خطيًا يسهل تتبعه بأوامر مثل `git log` و`git bisect`.

## متى تفضّل الدمج؟

- حين يكون الفرع **مشتركًا** ويعمل عليه غيرك: إعادة كتابة سجله تربك زملاءك وقد تضيّع عملهم.
- لدمج فرع مكتمل في `main` مع الاحتفاظ بأثر واضح لدخوله.
- حين تريد سجلًا يعكس ما حدث فعلًا دون تعديل.

**القاعدة الذهبية:** لا تُعِد تأسيس إيداعات دفعتها إلى فرع يستخدمه غيرك. أعد تأسيس عملك المحلي بحرية، واستخدم الدمج لما صار مشتركًا.
