## كيف يعمل `git rebase`؟

يأخذ `git rebase` الإيداعات (commits) التي أضفتها في فرعك، ثم يعيد تطبيقها واحدًا تلو الآخر فوق آخر إيداع في فرع آخر. والنتيجة سجلّ خطّي، كأنك بدأت عملك من آخر نقطة في ذلك الفرع.

لنفترض أن فرعك `feature` تفرّع من `main` عند الإيداع `B`، ثم أضاف أحدهم إيداعات جديدة إلى `main`:

```
قبل:
main:     A---B---C---D
               \
feature:        E---F

بعد git rebase main:
main:     A---B---C---D
                       \
feature:                E'---F'
```

لاحظ أن `E'` و`F'` إيداعات **جديدة** لها معرّفات مختلفة، لأن Git ينشئها من جديد فوق `D`. أما `git merge` فيُبقي الإيداعات كما هي، ويضيف «إيداع دمج» (merge commit) يربط الفرعين.

## مثال عملي

```bash
git switch feature
git fetch origin
git rebase origin/main        # أعد تطبيق إيداعاتك فوق أحدث main

# عند حدوث تعارض:
git status                    # اعرف الملفات المتعارضة
# عدّل الملفات ثم:
git add <file>
git rebase --continue         # أو git rebase --abort للتراجع

git push --force-with-lease   # لازم لأن السجل تغيّر
```

ولتنظيف إيداعاتك قبل فتح طلب الدمج (pull request):

```bash
git rebase -i HEAD~3          # دمج آخر 3 إيداعات أو تعديلها أو حذفها
```

## متى تفضّل `rebase` على `merge`؟

**استخدم `rebase` عندما:**

- تريد تحديث فرعك الخاص بآخر تغييرات `main` دون إضافة إيداعات دمج لا فائدة منها.
- تريد سجلًّا خطيًّا نظيفًا يسهل قراءته وتتبّعه بالأمر `git log` أو `git bisect`.
- تريد ترتيب إيداعاتك أو دمجها قبل مراجعة الشيفرة.

**واستخدم `merge` عندما:**

- يكون الفرع مشتركًا ويعمل عليه غيرك، لأن إعادة كتابة السجل تربك زملاءك.
- تريد الحفاظ على تاريخ العمل كما حدث، ومعرفة متى دُمج كل فرع.
- تدمج فرعًا مكتملًا في `main` وتريد إيداعًا واضحًا يسجّل هذا الدمج.

## القاعدة الذهبية

لا تُعِد كتابة إيداعات دفعتها إلى فرع يعتمد عليه الآخرون. استخدم `rebase` كما تشاء لترتيب عملك المحلي، واستخدم `merge` لكل ما هو مشترك.
