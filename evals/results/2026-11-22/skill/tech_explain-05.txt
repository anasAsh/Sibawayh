# الفرق بين العملية والخيط

**العملية (Process)** برنامج قيد التنفيذ، يمنحه نظام التشغيل مساحة ذاكرة مستقلة وموارد خاصة به، مثل الملفات المفتوحة ومتغيرات البيئة. لا تستطيع عملية أن تقرأ ذاكرة عملية أخرى مباشرةً، بل تحتاج إلى وسائل الاتصال بين العمليات (IPC) مثل الأنابيب (pipes) والمقابس (sockets).

**الخيط (Thread)** وحدة تنفيذ داخل العملية. تحتوي كل عملية على خيط واحد على الأقل، وقد تضم عدة خيوط تتشارك الذاكرة والموارد نفسها. ومع ذلك يحتفظ كل خيط بمكدسه (stack) وعداد تعليماته الخاص.

## أهم الفروق

| وجه المقارنة | العملية | الخيط |
|---|---|---|
| الذاكرة | مستقلة لكل عملية | مشتركة بين خيوط العملية الواحدة |
| كلفة الإنشاء | أعلى | أقل |
| الاتصال | عبر IPC، وهو أبطأ | مباشر عبر المتغيرات المشتركة |
| العزل | انهيار عملية لا يُسقط غيرها | خطأ في خيط قد يُسقط العملية كلها |
| التزامن | لا تحتاج غالبًا إلى أقفال | تحتاج إلى أقفال (locks) لحماية البيانات المشتركة |

## ملاحظة خاصة بلغة بايثون

في `CPython` يمنع قفل المفسر العام (GIL) أكثر من خيط من تنفيذ شيفرة بايثون في اللحظة نفسها. لذلك تناسب الخيوط المهام التي تنتظر الإدخال والإخراج (I/O)، مثل الشبكة والملفات. أما المهام الحسابية الثقيلة فتناسبها الوحدة `multiprocessing` التي تنشئ عمليات منفصلة.

## مثال

```python
import threading
import time

counter = 0
lock = threading.Lock()

def worker(name, n):
    global counter
    for _ in range(n):
        with lock:  # حماية المتغير المشترك
            counter += 1
    time.sleep(0.5)  # محاكاة انتظار عملية إدخال وإخراج
    print(f"{name} انتهى")

threads = [
    threading.Thread(target=worker, args=(f"الخيط {i}", 100_000))
    for i in range(3)
]

for t in threads:
    t.start()
for t in threads:
    t.join()

print("القيمة النهائية:", counter)  # 300000
```

يشغّل البرنامج ثلاثة خيوط داخل عملية واحدة، وتعدّل جميعها المتغير `counter` لأنها تتشارك الذاكرة:

- يمنع القفل `lock` حالة التسابق (race condition)، ولولاه لضاعت بعض الزيادات.
- تبدأ الدالة `start()` تشغيل الخيط، وتنتظر `join()` انتهاءه قبل طباعة النتيجة.
