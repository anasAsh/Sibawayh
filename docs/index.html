How Sibawayh is tested

كيف نختبر «سيبويه»؟

Sibawayh is a skill that makes an AI agent write correct Arabic and check it before answering. This page describes how we measure whether it works, and what the measurements do not show.

The request

اشرح مفهوم الـ caching في تطبيقات الويب لمدير غير تقني، وبيّن لماذا يجعل الموقع أسرع.

بدون Caching: كلما طلب زبون قهوة، يذهب الموظف إلى المخزن ويطحن البُن ويغلي الماء.

الـ Caching يحفظ الصفحة الجاهزة بعد أول مرة، فيحصل عليها كل زائر بعده فوراً.

Four tests, four questions

No single test covers a writing skill. The blind comparison measures the whole skill on realistic requests. The other three test parts of it that can be checked without a judge.

The blind comparison

The same agent answers the same requests twice, once with the skill and once without. A judge that cannot tell the two apart counts the errors in each answer.

  1. 100 requests

    20 each of emails, social posts, documentation, technical explanations and translations into Arabic. 68 are written in Arabic and 32 in English asking for Arabic. They are in evals/prompts.tsv.

    The first 50 were in use while the skill was being developed. The second 50 were written afterwards, and the skill was not changed after it answered them. The results below report the two halves separately.

  2. Two answers to each

    Claude Code answers every request in a fresh, empty folder. In the skill run the folder holds a copy of the skill; in the baseline run it holds nothing. Both runs have the same tools and ignore the user's own settings, so an installed copy of the skill cannot leak into the baseline.

  3. Blind pairs

    Each request and its two answers go into one file as Response A and Response B, in random order. The list of which is which stays outside the folder the judge can read.

  4. A judge from another model family

    GPT, run through Codex with read-only access, counts the errors in each response in five categories and says which response reads as more correct and natural. Claude does not grade its own output.

    All 100 pairs are judged three times, each time in a new random A/B order, because the judge's counts vary from one reading to the next.

  5. Unblind and check the bar

    The counts are mapped back to baseline and skill and divided by the number of words. The skill passes only if it meets all three conditions: no over-corrections, at most half the baseline's errors per 100 words, and no category worse than the baseline.

What the judge counts

  • Grammar

    Agreement, number and counted noun, case endings, verb mood. ثلاث مهندسين ← ثلاثة مهندسين

  • Spelling

    Hamza, ة and ه, ى and ي, tanween, joined or split words. إستخدام ← استخدام

  • Translationese

    English structures and idioms in Arabic words. تم إنشاء الملف من قبل المستخدم ← أنشأ المستخدم الملف

  • Register

    Dialect in formal text, and English words outside parentheses or code. الـ Caching ← التخزين المؤقت

  • Formatting

    Latin punctuation in Arabic text, spacing around punctuation, mixed digit systems, lines that start with a Latin word. نعم, ولكن? ← نعم، ولكن؟

  • Over-corrections

    A correct form changed into a wrong one. Forms that the Cairo Arabic Language Academy approves, such as يعتبر and حوالي, are not errors, and a skill that "fixes" them fails the test.

The judge's full instructions are in evals/ai_judge.md. It is told not to count an error when it is unsure.

The over-correction check

The skill's first rule is never to flag correct Arabic. To measure that, the checker runs on Arabic that has already been edited: 100 featured articles from Arabic Wikipedia, 806,509 words. Every error it reports is read in context by hand when a rule is added or changed.

Half of the articles were used to tune the rules. The other half were held out and used for no change.

SetWordsError flagsFalse
50 articles used for tuning416,602880
50 held-out articles389,9071030

The flags were real errors that featured articles still contain, such as إثنين، الإتجاه، شئ، يتسائل، خمسة عشرة سفينة.

Two weaker kinds of finding did less well. In the first review, automatic fixes made 1 wrong change in 278: a Persian letter cited on its own in a table of alphabets, which the rule now leaves alone. Warnings only ask the agent to look again at the context, and some of them are wrong, mostly on proper names and cited letters (the surname حتي, the wrestler بيغ شو).

Details: evals/corpus_check.md.

Recall: how many real errors the checker catches

A checker that never flags anything would pass the test above, so recall is measured twice.

Against people's corrections

Two public corpora in which annotators corrected every word by hand: ZAEBUC, essays by first-year university students (9,932 words), and QALB-2014, comments on news articles by native speakers (50,309 words). Recall is the share of the words they corrected that a checker finding covers.

Error typeStudent essaysNews comments

Hamza68%59%
ة and ه37%40%
ى and ي14%40%
All error types52%41%

"All error types" includes grammar, word choice and punctuation choices that a script cannot judge. The skill leaves those to the agent's own review checklist, so the checker's recall is not the skill's recall. When the checker does catch a single-word error, its suggestion matches the annotators' correction 80% of the time in the essays and 91% in the comments.

Against injected errors

A script takes clean lines from the held-out Wikipedia articles, puts one known error into each (for example ، becomes ,, or أ becomes ا), and checks whether the checker finds it. 200 sites per error type.

The trigger test

A skill that does not load does nothing. Twenty requests check that it loads when Arabic is involved and stays out otherwise:

  • 14 requests in Arabic or for Arabic output, including summarise, rewrite and proofread. All 14 loaded the skill.
  • 4 requests for English text or code only. None loaded it.
  • 2 requests for Egyptian and Gulf dialect. Both loaded it. For dialect the skill checks formatting only and must leave the dialect words alone; that part is read by hand.

The requests are in evals/triggers.tsv.

What these tests do not show

  • No native reader has scored the answers yet. AI models are only moderately reliable at judging Arabic grammar. The judge is from a different model family and works blind, but the size of the effect needs a human round to confirm. The answers and scores are public so that anyone can do it.
  • Each request was answered once per side. Answers vary from run to run, and that variation is not measured. One bad answer moves the total by about 0.05 errors per 100 words.
  • The judge is noisy. The same baseline answers score differently in each judging, so the change is compared within a judging and averaged over three.
  • One agent. All answers come from Claude Code. Other agents can load the skill but have not been measured.
  • Wikipedia is edited, not proofread, and the articles are the first 100 featured articles in category order, not a random sample.

Run it yourself

Everything is in the repository and uses only the Python standard library. Generating answers needs the claude command line tool and uses your own usage.

git clone https://github.com/anasAsh/Sibawayh && cd Sibawayh

python3 -m unittest discover -s tests -t .       # unit tests
python3 evals/run_triggers.py                    # trigger test

python3 evals/generate.py --mode baseline        # answers without the skill
python3 evals/generate.py --mode skill           # answers with it
python3 evals/pair.py --seed 1 judge key.csv     # blind A/B pairs; keep key.csv away from the judge
python3 evals/judge_report.py scores.csv key.csv # unblind, totals, pass or fail

python3 evals/fetch_wiki.py --limit 50           # over-correction check
python3 evals/corpus_check.py evals/corpus/wiki
python3 evals/inject.py evals/corpus/wiki        # recall with injected errors

Every answer, blind key and score file from the runs on this page is in evals/results/. If you read Arabic natively and want to score a set of pairs, open an issue.
